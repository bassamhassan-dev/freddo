# Sprint 13 — بانرات الصفحة الرئيسية (شرح بالمصري)

## الهدف
توثيق المتطلبات 5: الصفحة الرئيسية فيها 3 أماكن لبانرات (رئيسي سلايدر +
ثانوي شمال + ثانوي يمين)، والأدمن بيتحكم في المحتوى والترتيب والتفعيل
وفترة الحملة من غير ما حد يلمس الكود.

## اللي اتبنى

### الموديل
`Banner`: مكان (main / secondary_left / secondary_right)، عنوان ووصف ونص
زر بالعربي والإنجليزي، رابط صورة، رابط زر اختياري، ترتيب، تفعيل، وبداية
ونهاية حملة اختياريين. فيه حقل `cloudinaryPublicId` فاضي جاهز: توثيق 16
بيخطط لـ Cloudinary لكن مفيش حساب متظبط لسه، فالبانرات دلوقتي بروابط
صور مباشرة — ولما Cloudinary يتفعّل الترحيل هيبقى إضافة مش تكسير.

### الـ API
- `GET /api/banners?placement=` (عام): بيرجع **بس** البانرات النشطة اللي
  جوه فترة حملتها، مرتبة حسب sortOrder. أي بانر متوقف أو فترته لسه
  جاية أو خلصت مش بيطلع للعميل خالص.
- `GET/POST /api/admin/banners` و `PATCH/DELETE /api/admin/banners/:id`
  (أدمن): إدارة كاملة. الترتيب مجرد تغيير في sortOrder — مفيش endpoint
  منفصل لإعادة الترتيب (ممنوع over-engineering).

### التحقق (توثيق 5.3)
- رابط الصورة لازم يكون http/https.
- رابط الزر: http/https أو مسار داخلي يبدأ بـ `/` — كده `javascript:...`
  وأمثاله مرفوضة بالكود `INVALID_LINK` (وفيه test بيجرّبها فعلاً).
- لو فيه فترة حملة، النهاية لازم تكون بعد البداية.

### الواجهة
- الصفحة الرئيسية: سلايدر للبانر الرئيسي (بيعدّي كل 5 ثواني لو فيه أكتر
  من واحد، ونقاط تنقّل) + البانرين الثانويين جنب بعض. لو مفيش بانرات
  خالص، القسم مابيظهرش — الصفحة تفضل زي ما هي.
- تاب تامن في لوحة الأدمن «البانرات»: قائمة + فورم إنشاء/تعديل واحد
  فيه كل الحقول باللغتين.

## الاختبارات (4 جداد — المجموع 87/87 سيرفر)
1. العام بيفلتر بالمكان والتفعيل وفترة الحملة وبيحترم الترتيب.
2. مكان غلط في الـ query بيرفض بـ 400.
3. CRUD الأدمن: رفض صورة/رابط زر غلط، تعديل الترتيب والتفعيل، الحذف.
4. endpoints الأدمن أدمن-بس (401 للضيف و403 للعميل).

## قرارات متروكة لبسام
- رفع الصور نفسه: لما حساب Cloudinary يتظبط نضيف الرفع المباشر بدل روابط
  الصور اليدوية (الحقل جاهز).
